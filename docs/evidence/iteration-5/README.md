## Actual reconnect exchange

The final emulator run passes phases [A](reconnect-final-3/A/reconnect-mac.json), [B](reconnect-final-3/B/reconnect-mac.json), and [B-restart](reconnect-final-3/B-restart/reconnect-mac.json). The phone's raw reports are in each phase's `android-reconnect.log`. Both peers use the production eight-message encrypted reconnect protocol and durable test stores. Each phase has a distinct proof hash shared by both peers. Reserved sequence maxima rise from 5 to 10 to 15 on both sides. Endpoint hints change from A to B, then survive a process restart at B. Both peers check the persisted proof ID against the fresh handshake and compare the preceding proof after store recreation.

Each phase exchanges one authenticated ordinary `device.status` event in each direction. The Mac sends first after opening its real lifetime admission; the phone validates that event before replying through its production socket client. Android uses the production admission lease, accepted-socket capture and dispatch helper, with isolated lifecycle callbacks. This is core and helper coverage, not a complete `PlinkSessionController` or native app restoration test.

The [host cleanup](reconnect-final-3/host-cleanup.json) passes for all owned maps, child processes, test-package state and UUID-scoped files. [Ownership/provenance](reconnect-final-3/host-ownership.json) and the [removed state hashes](reconnect-final-3/reconnect-state-summary.json) remain available. The transport topology uses ADB loopback tunnels on the task-owned emulator. It does not verify physical interfaces, Android public `Network` binding, mDNS, hotspot activation or Internet routing.

The first run rejected ADB's blank line for an empty mapping inventory before opening a connection; the parser now accepts whitespace-only lines. It also tried to clean an Android run directory before instrumentation had created it. The supervisor now tracks instrumentation attempts separately from test-APK installation. The second run completed the phone handshake but timed out on the Mac's ordinary probe: the phone sent before the Mac had processed `done`. The final run uses the causal probe order described above. Neither failed run is credited as a pass. Arbitrary immediate-event reliability and crash/replay fault coverage remain separate requirements.
