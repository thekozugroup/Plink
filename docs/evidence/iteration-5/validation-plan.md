# Iteration 5 reconnect validation plan

The original plaintext fixture is frozen by Astra before production implementation. SHA-256: `d8b47bc8281c699aa2726d3caf966e11c0acbf6be1eda73e634cea4726aefe7d`. Independent structural sanity matched all 27 cases. Both platforms now pass the production-codec fixture tests; runtime acceptance remains pending.

Scope is the shared plaintext contract and fixture vectors for the eight `reconnect.*` messages. The vectors use the existing version-1 envelope shape from `shared/protocol/v1/screen-preview/cases.json`.

Fixture inventory: 27 cases total: 9 valid structural-admissibility cases and 18 rejection cases. The valid cases cover hello, challenge, proof, reverse, reverse_proof, ready, commit, done, and hello whitespace padded to exactly 2048 UTF-8 bytes. Rejection cases cover the original six plus exact 2049-byte plaintext, duplicate envelope fields, `requiresAck=true`, padded and noncanonical low-bit nonces, noncanonical timestamp, leading-zero IPv4, unexpected `p`, missing `r`, boolean `v`, unknown envelope field, and malformed UTF-8. All envelope IDs are canonical lowercase UUIDv4; source and target IDs remain nonempty existing test IDs; timestamps use whole-second UTC Z; synthetic endpoints are `192.168.50.10:45731` and `192.168.50.20:45731`; m, p, and r are fixed 32-byte values with exact hex and unpadded base64url forms recorded in `cases.json`.

The contract requires envelope plaintext <=2048 UTF-8 bytes and encrypted JSON <=4096 bytes. It requires `requiresAck=false`, exact envelope fields, exact per-message payload fields, integer token `v=1`, canonical 43-character unpadded base64url nonces, numeric IPv4:port endpoints, and rejection of duplicate keys, unknown fields, nulls, coercion, float forms, exponent forms, malformed UTF-8, and noncanonical timestamps. Runtime startup clauses were revised separately; this augmentation changes no wire fields.

After Astra hashfreeze, both platform codecs should run these shared vectors and compare structural admissibility and rejection reason. This is parser/codec evidence only. It does not prove runtime network behavior, observed socket binding, endpoint migration, mDNS discovery, hotspot joining, offlink rejection, or Internet route attribution.

Production offlink rejection and endpoint provenance cannot be proven purely on the wire. The encrypted fixtures below exercise the codec's raw-wire byte limit; actual socket allocation limits and network routing require separate runtime tests.

Supplemental immutable inputs added by Astra during implementation: 28 network-policy cases in `network-cases.json`, 13 independently generated encrypted vectors in `encrypted-vectors.json`, and 3 HMAC/filename vectors in `endpoint-store-vectors.json`. The encrypted generator first checks its AES-GCM ciphertext and HMAC against an existing screen-preview golden vector. Encrypted vectors test authenticated decoding and actual raw-wire byte limits; they do not require both serializers to emit the same JSON key order. Each vector uses isolated replay state and a clock fixed to `issuedAt`.

The pre-implementation RED baseline compiled both platform fixture tests and rejected all nine positive plaintext cases as expected. Android initially used a documented strict UTF-8 test adapter; the parent subsequently changed the tests to the production `PlinkEnvelope.decode(ByteArray)` entry point. The first integrated Swift tests exposed an ASCII digit parser defect rejecting all positive vectors; its production fix passes the rerun. No runtime or original acceptance credit follows from fixture generation or structural sanity.

An independent source review identified missing canonical checks for the authenticated outer `issuedAt`. Astra added five supplemental cases in `outer-timestamp-vectors.json`, SHA-256 `3d52bb3664f81603fdc42b824e74517293946aa795bb89512177371cd6562b9c`, preserving all four previous fixtures byte for byte. One canonical case must pass. Four fractional/offset cases must fail, including altered wire timestamps with the original canonical authentication, which tests whether a decoder incorrectly erases the spelling before validation. The separate generator reproduces the original encrypted hello exactly before generating these cases. Both platform tests consume the same new file and pass.

The parent found that Swift's initial literal regular expression could miss a Unicode-escaped `type` property or event name. Ten additional frozen cases in `classification-cases.json`, SHA-256 `a271cc963d9fbc3bde517e7a59eba45c9e66768770a12685f0eb51af84ce3002`, test two valid escaped spellings and eight invalid combinations with duplicates, unknown fields, float/exponent tokens, or a fractional timestamp. The selected fix classifies the actual decoded event, then requires the strict raw validator for reconnect messages. Both platforms consume these same cases; no earlier fixture was changed.
