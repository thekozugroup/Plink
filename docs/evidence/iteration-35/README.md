# Android companion registration and capability diagnostics

Plink now offers Android's ordinary Bluetooth companion-device picker after encrypted pairing. The picker matches the adapter address received from the authenticated Mac. The registration is bound to the saved device ID, public key, adapter address and Android association ID. Notification access uses Android's companion permission dialog when that registration is valid, with normal Settings as a fallback. Removing registration preserves the encrypted Plink pairing.

The implementation follows the [Android companion-device guide](https://developer.android.com/develop/connectivity/bluetooth/companion-device-pairing). It requests no privileged permission, profile or system-data transport. A debug-only, permission-protected receiver reports bounded platform capabilities from a separate process; it does not start a Plink session or change device settings. Release builds exclude that receiver.

Regression checks cover consent cancellation and late callbacks, pairing rollback, ID/key/address changes, known-ID cleanup, unknown-association preservation, Settings fallback, metadata validation and redaction, atomic admission checks, address preservation during temporary unavailability, and cancellation while waiting for the pairing mutex. All 640 automated tests pass: 293 Android and 347 Swift. Android debug, release and instrumentation APK builds pass. Android lint reports zero errors and 43 warnings. Swift build, Mac packaging, signature validation, shared fixtures and whitespace checks pass. See [verification.json](verification.json) for commands, binary hashes and limits.

No ADB device was attached. Native Bluetooth consent, notification-access UI and device delivery remain untested on these builds. No app was installed and no pairing, phone setting or permission was changed during this checkpoint. No task-created scratch files remain; intended builds and this evidence are retained.

This is an implementation checkpoint, not complete product acceptance. The [Continue On API](https://developer.android.com/develop/better-together/continue-on/enable-support) describes activity handoff; this companion registration does not enroll macOS as a receiver, mirror arbitrary app tasks, fix cellular audio or establish native notification artwork. Those outcomes remain open. The original acceptance evaluator also rejects an existing device-addendum hash mismatch. Its frozen hashes and criteria were left unchanged; no new acceptance score is claimed.
